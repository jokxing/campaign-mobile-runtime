## 必须遵守的开发规范

1. `app/api/<业务>.ts` 负责 URL、HTTP 方法、参数、响应类型；不操作页面状态、toast、路由或业务缓存。新增接口先在所属模块定义具名函数。
2. `app/composables` 负责加载状态、缓存、并发、降级及连接生命周期；`app/pages` 负责路由和交互；展示组件优先通过 props/emits 通信。
3. 动态路径参数统一编码，查询使用 `query`，提交使用 `body`。API 抛出的错误由调用方处理，不伪造成功响应。
4. 共享协议放 `shared`；仅前端使用的模型放 `app/types`。TypeScript 类型不能代替服务端输入验证或远端配置的运行时校验。
5. SSR 中禁止用模块级可变变量保存用户相关请求、状态和缓存；缓存必须明确作用域、键和失效策略。
6. 所有异步交互覆盖 loading、空数据、失败和重试；写入请求避免重复提交，失败保留用户输入。
7. SSE、定时器和事件监听器明确创建者、释放时机、重连策略；异步回调必须处理异常。
8. PR 至少通过 `npm run check:api`、`npm run typecheck` 和 `npm run build`，涉及行为变更时增加对应场景验证。

边界脚本是逐行文本检查，并非 AST 分析；可捕获常见写法，但不能证明不存在别名调用、跨行构造地址等绕过。API import 允许使用 `~/api/...`；文档和注释若命中规则应人工确认，不能为了通过检查把业务代码搬入 API 目录。
